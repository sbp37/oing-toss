# 원스토어 업로드 순서

만들어진 파일은 셋이다. 셋 다 같은 키(`oing-upload`, 지문
`B3:86:85:F8:6E:8A:9F:80:69:FA:26:77:5E:BB:D7:DE:13:43:F5:65:B1:62:D5:A4:89:94:0B:79:4C:E2:7E:F6`)로
서명돼 있다.

| 파일 | 무엇 |
| --- | --- |
| `oing-1.0.0.aab` | 앱 번들. 앱 서명 키를 등록해야 올릴 수 있다 |
| `oing-1.0.0-universal.apk` | 단일 APK. 키 등록 없이 그냥 올린다 |
| `oing-upload.jks` | 서명 키. 절대 잃어버리면 안 된다 |

## 실제로 고른 길 — PEPK 내보내기 (완료)

원스토어 서명키 화면에서 "앱 서명 사용(권장)" + "Java Keystore의 키 내보내기 및
업로드"를 골랐다. "앱 서명 사용 안함"은 비활성이라 APK만 올리는 길은 선택할 수
없었다.

`oing-upload.jks`에서 뽑은 결과물은 `oing-upload-pepk.zip`이고 안에 두 개가 있다.

| 파일 | 내용 |
| --- | --- |
| `encryptedPrivateKey` | 스토어 공개키로 암호화된 개인키 |
| `certificate.pem` | 인증서. SHA-256이 키스토어의 것과 동일함을 확인했다 |

올리는 순서는 화면 번호 그대로다.

1. PEPK 도구 다운로드 — 끝
2. 명령 실행해서 ZIP 생성 — 끝 (`oing-upload-pepk.zip`)
3. **생성된 ZIP 업로드** → `oing-upload-pepk.zip`
4. 새 업로드 키 생성은 선택사항이라 건너뛴다. 지금 키가 앱 서명 키이자 업로드
   키가 된다
5. 완료 → 앱 등록 화면의 바이너리 항목에 `oing-1.0.0.aab`

ZIP은 한 번 쓰고 버리는 물건이 아니다. `.jks`와 함께 백업해 둔다.

## 참고 — APK로 올릴 수 있다면

원스토어는 자체 서명한 APK를 그대로 받는다. 앱 서명 키 등록도, PEPK도, 키를
외부에 넘기는 절차도 전부 없다. **`oing-1.0.0-universal.apk` 한 개만 올리면
끝난다.**

이 게임에서는 APK와 AAB의 실질적 차이가 거의 없다. AAB가 크기를 줄여주는 것은
기기별로 다른 네이티브 라이브러리나 화면밀도 리소스를 갈라낼 때인데, 이 앱의
내용물은 웹뷰가 읽는 그림·소리 파일이라 어느 기기에서든 똑같이 필요하다.
갈라낼 것이 런처 아이콘 정도뿐이라 절감폭이 수백 KB에 그친다.

## AAB로 올려야 한다면

AAB는 스토어가 기기별 APK를 만들어 서명하기 때문에 서명 키를 스토어가 알아야
한다. 원스토어 앱 서명 설정에서 고르는 방식에 따라 할 일이 갈린다.

- **원스토어에서 앱 서명 키 생성** — 스토어가 자기 키를 만들고, 우리 키는
  업로드 키가 된다. 우리가 내보낼 것이 없으니 `oing-1.0.0.aab`를 그냥 올리면
  된다. 선택지에 있으면 이쪽이 제일 간단하다.
- **Java Keystore의 키 내보내기 및 업로드 (PEPK)** — 우리 키를 스토어에 넘기는
  방식. 그 화면이 주는 `pepk.jar`와 암호화 공개키가 있어야 하고, 키는 계정마다
  달라서 콘솔에서 직접 받아야 한다.

  ```sh
  java -jar pepk.jar \
    --keystore=oing-upload.jks \
    --alias=oing-upload \
    --output=oing-upload-pepk.zip \
    --include-cert \
    --rsa-aes-encryption \
    --encryption-key-path=<콘솔이 준 PEM 경로>
  ```

  콘솔이 PEM 파일 대신 긴 16진수 문자열을 주면 마지막 줄을
  `--encryptionkey=<문자열>`로 바꾼다. 실행하면 키스토어 비밀번호와 키
  비밀번호를 차례로 묻는다. 나온 `oing-upload-pepk.zip`을 그 화면에 올리고,
  그다음 `oing-1.0.0.aab`를 바이너리 항목에 올린다. **순서가 중요하다 — 키
  등록이 먼저다.**

## 구글 플레이에 올릴 때

플레이는 AAB만 받는다. 앱을 만들 때 Play 앱 서명이 기본으로 켜지는데, 이때
플레이가 앱 서명 키를 새로 만들고 우리 키는 업로드 키가 된다. 즉 **PEPK 없이
`oing-1.0.0.aab`를 그대로 올리면 된다.** 우리 키를 앱 서명 키로 직접 쓰고
싶을 때만 PEPK가 필요하다.

## 어느 쪽이든 공통

- 버전을 올릴 때마다 `android/app/build.gradle`의 `versionCode`를 1씩 올린다.
- 서명 키는 바뀌면 안 된다. 지문이 위와 같은지 확인:
  `keytool -printcert -jarfile <파일>` (APK는 `-jarfile` 대신 설치 후 확인하거나
  `apksigner verify --print-certs` 사용)
