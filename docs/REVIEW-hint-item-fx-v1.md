## 1. 무엇을 왜 고쳤나 (검수 포인트)

### ① 힌트 — 선을 버리고 빛으로

사용자 피드백은 **"라인을 그었더니 더 알아보기 어렵다, 서로 막 엮인다"**였다.
원인은 선이 네 겹 동시에 그려지고 있었던 것:

| 겹 | 어디 |
| --- | --- |
| 칸별 안쪽 민트 테두리 | `.tile.is-hint-area:not(.is-hint)` inset box-shadow |
| 숫자 칸 민트 outline | `.tile.is-hint` outline 2px |
| 바깥 사각형 테두리 | `.hint-region` border 4px(→2.5px) |
| 모서리 장식 4개 | `.hint-region > i` |

격자 자체가 선으로 된 판이라 선을 더할수록 경계가 늘어난다.
**선을 전부 없애고 규칙 하나만 남겼다: 영역 밖은 가라앉고, 영역은 밝게 뜬다.**

- 영역 밖 `filter: saturate(.4) brightness(.86)` — 힌트가 떠 있는 2.2초만
- 영역 안(빈 칸 포함) `filter: none` — 섬이 끊기면 묶음이 아니라 점으로 읽힌다
- 숫자 칸은 흰 키라인 2px + 기존 그림자만
- 경계는 `.hint-region`의 부드러운 광륜 하나 (border 0)
- "합10 여기!" 칩은 그대로

**검수 방법**: 2칸 답과 3×3 답 두 모양을 모두 띄워 볼 것. 넓은 답에서
칸마다 상자가 서지 않는지가 핵심이다.

### ② 아이템 착지 파문

날아온 아이콘이 칸에 **닿는 프레임**에 파문이 한 번 퍼진다.
`js/ui.js` `showBoardItemDrops()`에서 `.item-land-ring`을 붙이고
기존 정리 타이머(1420ms + index*80)에서 같이 제거한다.

- 색은 계열별: 폭탄류 다홍 / 시간류 하늘 / 클로버 초록
- 희귀 아이템(`RARE_BOARD_DROP_IDS`)은 더 굵고 느리게
- transform/opacity 일회성 → **상시 비용 0**

### ③ 가려지던 플로트 둘 (원인까지 규명)

- **`+N초`(시간 게이지 위)**: 게이지가 `overflow:hidden`인데 `position`이 없어
  `::after` 플로트가 엉뚱한 조상 기준으로 자리를 잡고 HUD 패널 뒤로 떠올랐다.
  게이지에 `position: relative; overflow: visible`을 주고, 잘림이 사라진 대신
  채움 막대 `i`에 `border-radius: 999px`를 직접 줘서 둥근 끝을 지켰다.
  보너스가 떠 있는 1.1초 동안만 `z-index: 30`.
- **`N판 +M초`(판 중앙 배지)**: 타일 뒤에 깔려 반쯤 가려졌다. `z-index: 44` +
  `isolation: isolate`.

### ④ 홈 문구 `합이10이면`

`.home-instruction`이 flex라 텍스트 노드 사이 공백이 전부 죽어 붙어 있었다.
문장을 `<span class="home-instruction-copy">` 하나로 감싸 인라인 흐름을 돌려줬다.
렌더 확인: `사각형으로 묶어서 합이 10이면, 뿅!`

### 건드리지 않은 것

- **`i` 버튼 정렬** — 사용자가 "그냥 둬, 내 결정"이라고 명시했다. 건드리지 말 것.
- 게임 규칙, 점수 공식, 밸런스, 보드 생성 — 하나도 안 건드렸다.

## 2. 검수 방법 (내가 쓴 것 그대로)

브라우저 없이 눈으로만 보면 놓친다. 아래가 실제로 쓴 방법이다.

- Playwright + Chromium(`/opt/pw-browsers/chromium`), **실제 터치 이벤트**로 조작
  (CDP `Input.dispatchTouchEvent`). 마우스로 끌면 폰에 없는 `:hover` 재계산이
  섞여 성능 수치가 오염된다.
- 폭 360 / 390 / 430 세 가지. `AGENTS.md`가 요구하는 검수 폭이다.
- 발열은 `Emulation.setCPUThrottlingRate 4` + 3연판으로, `Performance.getMetrics`의
  `Nodes` / `JSEventListeners` / `JSHeapUsedSize` 증가 여부로 본다.
- 유휴 애니메이션은 `document.getAnimations().filter(a => a.playState === 'running')`.
  이게 발열의 기준선이다.

### 내가 잰 값 (같은 조건에서 재현되어야 함)

| 항목 | 값 |
| --- | --- |
| 테스트 | 167개 통과 |
| 드래그당 스크립트 (4× 스로틀) | 16~23ms (main 12~25ms와 같은 대역) |
| 드래그당 스타일 재계산 | 49~67회 (main 51~60회) |
| 3연판 노드 / 리스너 / 힙 | 1375~1922 / 102~113 / 3MB — 증가 없음 |
| 유휴 애니메이션 추가 | **0개** (새로 넣은 것은 전부 일회성) |

### 주의: 플레이키 테스트

`tests/board.test.mjs`의 `stage 6: some boards carry full-clear certificates`는
**시드에 따라 흔들린다.** `main`(770d107)에서도, 내 변경을 `git stash`한
상태에서도 같은 실패가 재현됐다. 이 브랜치가 만든 문제가 아니다.
검수 중 이 테스트가 빨갛게 나오면 한 번 더 돌려볼 것.

## 3. 내가 찾았지만 고치지 않은 것

우선순위 순. 전부 이 브랜치 범위 밖이라 손대지 않았다.

1. **판갈이 배지가 또렷하게 안 선다** — 두 번의 계측 모두 최대 불투명도
   ~0.66에서 지나갔다. 의도된 페이드일 수도 있으니 **먼저 의도를 확인**하고,
   의도가 아니면 키프레임을 볼 것. 보상 문구치고 흐릿하다.
2. **430px에서 보드 아래 여백이 크다** — 시작판이 6×6이 된 뒤에도 큰 폰에서
   화면이 허전하다. 보드 최대 폭 제한(`--board-edge`)을 손봐야 한다.
3. **결과 시트에 "이번 판 기록" 헤더가 없다** — 시트가 무엇의 기록인지
   첫 줄이 말해주지 않는다.
4. **도움말 데모의 손가락이 숫자를 가린다** — `2 + 3 + ?`로 읽힌다.

## 4. 이어서 할 일 (점수가 가장 크게 오르는 순서)

마감은 거의 끝났다. 남은 레버는 **코드가 아니라 게임 설계** 두 개다.
둘 다 밸런스 결정이 필요해서 사용자 확인 후 진행할 것.

### A. 후반 밀도 (난이도 72점 → 예상 78)

6×8 판에서 답이 큰 사각형 위주로만 남아, 어려운 게 아니라 **눈이 피곤하다.**
게임 스스로 90초 이후 20초 간격으로 "막혔냥? 여기 봐보라냥!"을 띄운다.

- 방향: 판이 커질수록 2~3칸 답의 **최소 보장 개수**를 명시적으로 두고,
  대신 큰 답의 점수를 더 벌린다.
- 근거 데이터: `HANDOFF.md` 4절의 봇 측정 표. 같은 방식으로 재측정할 것.

### B. 판 단위 단기 목표 (중독성 72점 → 예상 80)

카드 1~2장을 얻고 나면 남은 카드가 전부 장기 조건(20,000칸, 30일 출석)이라
**"이번 판의 목표"가 사라진다.**

- 방향: "이번 판 고양이 5마리" 같은 판 단위 미션 하나.
- 주의: 새 메타 시스템을 만들지 말 것. 이미 있는 카운터를 쓰는 한 줄이면 된다.

## 5. 이 저장소에서 모르고 건드리면 깨지는 것

`HANDOFF.md` 2절이 본문이다. 이번 작업에서 실제로 걸린 것만 다시 적는다.

- **폰트 서브셋 가드**: `index.html` / `css/` / `js/`에 서브셋에 없는 한글이
  하나라도 새로 들어가면 `tests/fonts.test.mjs`가 실패한다. **주석의 글자도
  포함된다.** 이번에도 CSS 주석 때문에 두 번 걸렸다.
  고치는 법: `python3 tools/build-jua-subset.py && python3 tools/build-pretendard-subset.py`
  (원본은 `/tmp/Jua-Regular.ttf`, `/tmp/PretendardVariable.woff2` — 없으면 다시 받아야 함).
  `.md` 파일은 검사 대상이 아니다.
- **CSS는 덮어쓰지 말고 덧붙인다**: `css/play-layout-v1.css`는 뒤로 갈수록
  이기는 구조다. 이번 변경도 전부 파일 끝에 덧붙였다.
- **`animation-fill-mode: both/forwards`**: 끝난 애니메이션이 레이어를 살려둬
  발열의 원인이 된다. 새로 넣은 `.item-land-ring`은 `forwards`를 쓰지만
  타이머로 DOM에서 제거되므로 남지 않는다. 같은 패턴을 지킬 것.
