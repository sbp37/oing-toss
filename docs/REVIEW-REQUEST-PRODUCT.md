## 0. 반드시 먼저 읽을 것 — 이걸 모르면 진단이 틀어진다

### (가) 채널마다 게임이 다르다. 하나로 뭉뚱그려 평가하면 안 된다

같은 코드가 세 곳에 나가는데, **런타임에 켜지는 기능이 채널마다 다르다.**
`js/leaderboard.js`의 `isAppsInTossWebView()`가 토스 웹뷰가 심어주는 두 값
(`ReactNativeWebView`, `__appsInTossConstants`)을 보고 판단하기 때문이다.

| | 토스 미니앱 | **구글플레이(예정)** | 웹 |
| --- | --- | --- | --- |
| 보상형 광고 (이어하기·도움팩) | ✅ | **❌ 없음** | ❌ |
| 리더보드 (토스 게임센터) | ✅ | **❌ 없음** | ❌ |
| 친구 초대 리워드 | ✅ | **❌ 없음** | ❌ |
| 게임 본체·카드·기록·도전장·공유 | ✅ | ✅ | ✅ |

**즉 구글플레이 첫 출시 버전은 수익이 0이고 랭킹도 없다.** 이건 실수가 아니라
"지금 단계의 목적은 유통(사람들이 설치할 곳)이지 수익이 아니다"라는 판단에
따른 것이다. 이 판단 자체가 옳은지도 평가해 줘.

**따라서 "광고 수익화 구조"와 "랭킹 경쟁 동기" 항목은 채널을 나눠서 답해라.**
한 점수로 뭉치면 의미가 없다.

### (나) 절대 제안하면 안 되는 것 (제작자가 정한 제약)

- **자체 랭킹 서버·계정·로그인·닉네임·치팅 방지를 만들지 않는다.**
  1인 개발이고, 서버 하나 띄우면 계정·닉네임·어뷰징 대응이 줄줄이 딸려 온다.
  이 원칙이 프로젝트를 지금까지 가볍게 유지한 이유다.
  → "주간 리더보드를 백엔드로 만들어라" 같은 제안은 이 제약 위반이다.
  → 다만 **구글 Play Games Services는 예외**다. 구글이 계정·닉네임·순위를
    다 갖고 있고 우리는 점수만 던지므로 토스 게임센터와 같은 구조다.
    **PGS는 일간/주간/전체 순위가 기본으로 딸려 온다**(토스 SDK에는 주기
    옵션이 아예 없다 — `setLeaderboardScore({score})`가 전부).
- `js/leaderboard.js`와 토스 SDK 래퍼는 검증된 버그 없이는 안 건드린다
- **한 판에 점수 제출은 정확히 한 번** (`finishClassic`의 제출 위치 유지)
- 기존 드래그 조작과 보드 생성의 full-clear 보장 유지

### (다) 이미 만들어져 있는 것 — 또 만들라고 하지 마라

이전 자문에서 "지금 당장 만들어라"고 한 것 중 상당수가 이미 있다.

| 이미 있는 것 | 어디 |
| --- | --- |
| **도전장** — 내 점수를 링크(`?vs=8235`)로 보내면, 받은 사람은 그 점수를 목표로 들고 시작. 홈 배너 + 시작 카운트다운에 목표가 뜨고, 넘으면 되받아치는 문구로 바뀜 | `js/challenge.js` |
| **다음 목표 한 줄** — 결과창의 '한 판 더!' 버튼 위, 그리고 시작 카운트다운에. 친구 기록/내 최고기록/카드 중 "몇 판 더 걸리나"가 제일 작은 하나만 | `js/data.js` `nextGoalLine` |
| **오잉 카드 9장** + 개봉 연출(3D 뒤집기) | `js/data.js` `OING_CARDS` |
| **별사탕 → 고양이 먹이기** 펫 요소 | `js/candy.js` |
| **고양이의 모험** 장면 수집 | |
| 보상형 광고 2종, 친구 초대 리워드, 공유(글+그림+링크) | |
| 판갈이 시간 추가, 콤보 배율, 보드 아이템(힌트·셔플·폭탄·시계) | |

**평가는 해라. 다만 "새로 만들어라"가 아니라 "지금 구현이 제 역할을 하는가"로
봐라.** 예: 도전장은 있는데 공유 문구가 아직 "자랑"에 가깝다("오잉게임에서
8,235점 냈다냥! ... 이겨보라냥!") — 받는 사람이 주인공이 아니다. 이런 식의
지적이 유용하다.

### (라) 지난 검수에서 지적받아 이미 고친 것 — 또 지적하지 마라

바로 전에 다른 검수를 한 번 받았고, 지적이 대체로 옳아서 전부 고쳤다.

- 광고가 **15초만 떠 있으면 보상 이벤트 없이도 지급**하던 것 → 제거.
  `userEarnedReward`를 실제로 받았을 때만 지급한다. 대신 순서 역전용 유예를
  1.5초→3초로 늘리고, **보상을 못 받았을 때 그 사실을 알리는 안내**를 넣었다
  (예전에는 광고를 보고 왔는데 아무 말도 없었다)
- `nextGoalLine`이 "남은 비율"로만 골라서 **27판·78판짜리 목표**를 "한 판 더
  할 이유"로 내밀던 것 → 그 사람 자신의 판당 평균으로 "몇 판 남았나"를 재는
  방식으로 교체
- **도전장 링크로 온 신규 유저에게 정작 도전장이 안 뜨던 것** → 거리와 무관하게
  항상 최우선
- `.ait` 빌드 뒤 웹 배포본 복구가 실패에 안전하지 않던 것 → `finally`로
- 발열 수치 재현 스크립트 없던 것 → `tools/measure-repaint.mjs`로 커밋
- 카드 개봉 창 접근성(role/aria-modal/포커스/키보드) → 추가
- **그리고 구글플레이 빌드에서 공유 링크가 죽어 있던 것**(Capacitor가
  `https://localhost/`에서 띄워서 `https://localhost/?vs=8235`가 나갔다)
  → 공개 웹 주소로 바꿈

## 1. 현재 상황 — 숫자를 부풀리지 않는다

**실제 사용 규모 (여기가 핵심이다)**
- 어제 하루 토스 인앱 광고 노출 **29회**, 예상 수익 **3,259원**
- 그중 21회가 "30초 더"(TIME UP 이어하기). 한 판에 한 번만 뜨므로
  = 어제 광고를 보고 이어한 판이 21판
- 리뷰는 있지만 **전부 제작자의 지인**이다
- **즉 유의미한 사용자 데이터가 없다**

**게임성 결정의 근거가 시뮬레이터다**
난이도·보드 성장 곡선·점수 곡선은 전부 헤드리스 봇
(`tools/classic-balance-sim.mjs`)을 돌려서 정했다. **실제 사람이 아니다.**
봇 기준 30판 평균:

| 유형 | 평균 점수 | 평균 시간 | 평균 도달 판 |
| --- | --- | --- | --- |
| 초보 | 1,775 | 2.4분 | 4.1 |
| 보통 | 5,983 | 2.7분 | 6.7 |
| 숙련 | 15,197 | 3.0분 | 10.8 |

**로딩** (Chromium, 느린 4G + CPU 4배 스로틀)
- 첫 그림 2.65초 / 시작 버튼 6.46초 / 네트워크 조용 16.7초, 총 2.6MB
- 토스/구글플레이는 번들이 로컬이라 다르다. 대신 첫 설치 다운로드가 9.1MB
  (그중 BGM mp3가 2.58MB — 이미 128kbps라 태그 낭비는 없다)

**구글플레이 상태**
- 개발자 계정 결제 완료, 맥 있음, 테스터는 외주로 해결 예정
- 스토어 등록 문구·그래픽 자료 준비 완료 (`store/GOOGLE-PLAY.md`)
- 앱 이름 후보: `오잉게임 - 숫자 합 10 퍼즐`
- ⚠️ 개인 개발자 계정의 클로즈드 테스트 요건이 걸릴 수 있음

## 3. 반드시 구체적으로 답할 질문

**A. 이 게임의 진짜 강점은?**
다른 숫자 퍼즐과 비교해 사용자가 기억할 요소가 실제로 있는지.
"귀여운 고양이" 같은 피상적인 답 말고 **게임 루프 자체의 차별화**를 봐라.
(참고: 이 장르의 원조 격인 사과게임/Fruit Box는 고정 보드 1회성인데,
오잉은 판을 다 지우면 시간이 추가되며 보드가 커진다. 이 구조 차이가
실제로 의미 있는 차별화인지 판단해 달라.)

**B. 반대로 묻힐 가능성이 높은 이유는?**
한 번 하고 나가거나 아예 클릭하지 않을 이유를 우선순위대로.

**C. 지금 가장 큰 문제 5개.** P0/P1/P2로 나누고 각각:
문제 → 사용자에게 어떤 악영향 → 구체적 수정안 → 예상 효과 → 개발 난이도

**D. 절대 지금 건드리지 말아야 할 것.**
이미 괜찮은 부분을 뜯어서 역행하는 걸 막고 싶다.

**E. 차별화를 더 만들려면?**
새 기능을 무작정 늘리지 말고 **현재 구조 안에서** 가능한 방향 우선.
아래 후보를 각각 *효과 / 차별화 기여 / 리텐션 기여 / 개발량 / 추천도*로:
- 합10 퍼즐 자체를 더 강하게
- 고양이/별사탕 펫 강화
- 수집 카드/장면 강화
- 랭킹 경쟁 강화 (구글은 PGS 주간 순위가 공짜로 딸려 온다는 점 감안)
- 친구 공유/도전 강화 (도전장은 이미 있다 — 공유 문구가 약한 게 문제)
- 일일 미션/챌린지
- 다른 신규 메타

**F. 유입이 거의 없는 지금, 광고비를 태우는 게 맞나?**
**게임이 아직 부족한 단계인지, 제품은 충분하고 유입만 문제인지 구분해 줘.**
돈 쓰기 전에 확인해야 할 지표나 테스트가 있다면 **최소 비용 기준**으로.
(참고: 광고 노출 1회당 약 100원. 유저 획득 비용과 비교해 판단해 달라.)

**G. 스토어에서 처음 본 사람 기준 평가.**
`store/GOOGLE-PLAY.md`에 앱 이름·짧은 설명·자세한 설명이 적혀 있고,
그래픽 자료는 `store/google-play/`와 `store/screenshots/`에 있다.
**그것만 보고 "다운로드하고 싶다"가 생기는지** 판단하고, 부족하면 어떤
메시지로 바꿔야 하는지 알려 줘.
(제약: 다른 앱 이름(예: "사과게임")을 메타데이터에 넣는 것은 구글 정책
위반이라 못 쓴다. 일반 낱말로 같은 검색 수요를 받아야 한다.)

**H. 시장 생존 가능성.** 아래 중 하나를 고르고 이유를 숨기지 말고:
가능성 높음 / 가능성 있음 / 애매함 / 구조적 개선 필요 / 현재 상태로는 어려움

**I. 채널 전략.**
토스는 발견성이 거의 없다는 게 지금까지의 판단이다(어제 노출 29회가 근거).
그래서 무게중심을 구글플레이로 옮기려 한다. **이 판단이 맞나?**
토스에 남길 것과 구글에 걸 것을 나눠서 말해 줘.

## 5. 검수 태도

- **칭찬보다 발견이 중요하다.** 점수가 높아도 "왜 100점이 아닌지" 적어라.
- **이전 작업자(AI)가 쓴 주석과 자기평가를 사실로 믿지 마라.** 코드로 직접
  확인해라. 저장소 주석은 한국어로 길게 쓰여 있는데, 그중 일부는 그때의
  추론이지 검증된 사실이 아니다.
- **0-(다)에 적힌 이미 있는 기능을 또 만들라고 하지 마라.**
- **0-(라)에 적힌 이미 고친 것을 또 지적하지 마라.**
- **0-(나)의 제약을 어기는 제안을 하지 마라.**
- 큰 리디자인을 쉽게 권하지 마라.
- 신규 기능 추가보다 **현재 게임의 재미를 더 또렷하게 만드는 수정**을 우선.
- **개발량 대비 효과가 큰 순서로** 추천해라.
- "유저 테스트 해봐라"로 떠넘기지 마라. 코드와 현재 구조만으로 판단 가능한
  데까지 먼저 판단해라. (실제로 유저가 없어서 그 조언은 실행이 안 된다.)
- 듣기 좋은 답보다 **이 앱을 살리는 데 도움이 되는 답**을 줘라.
