# 다음 목표 한 줄 (v1 설계)

상태: **설계만. 구현 전.** 심사 제출이 끝난 뒤에 착수한다.

## 무엇을 고치려는 것인가

오잉은 스코어 어택인데 **쫓아갈 대상이 없다.**

토스 게임센터 랭킹은 상위 몇 명과 내 등수만 보여주고, 바로 위 사람의 점수는
안 보인다. "12등은 몇 점이지" "200점만 넘으면 잡는데" 같은, 스코어 어택을
스코어 어택으로 만드는 감각이 통째로 빠져 있다. 그리고 그 화면은 토스가
그리므로 우리가 고칠 수 없다.

자체 랭킹 서버는 만들지 않는다(계정·닉네임·치팅 방지가 줄줄이 딸려 온다).
대신 **게임 안에서 다음 한 판의 이유를 눈앞에 놓는다.**

## 이건 새 기능이 아니다

필요한 부품이 거의 다 있다. 자리만 틀렸다.

| 부품 | 지금 어디에 |
| --- | --- |
| `isRecordInReach(score, best)` — 최고기록 25%(최소 1,500점) 이내인가 | `js/data.js` |
| `"N점만 더!"` | '한 판 더!' 버튼 라벨로만, 조건부 |
| `최고기록 도전 N%` 미터 | 결과창 |
| 카드 9장 + 수치 조건 + `current` / `progress` | `oingCardRows()`, 내 기록 갤러리 |
| 누적 카운터(`runs` `cats` `bigClears` `cellsCleared` `playDays` `bestScore`) | `storageAdapter` |

카드 조건은 이미 **숫자로 된 다음 목표**다(`한 판 10,000점`, `지운 칸 20,000개`,
`5칸 이상 300번` …). 사다리가 있는데, 재시도를 결정하는 자리(결과창)가 아니라
찾아 들어가야 하는 자리(갤러리)에 있을 뿐이다.

**할 일은 "만들기"가 아니라 "고르기"다.**

## 핵심: 후보 중 하나만 고른다

결과창에는 이미 점수·비교 문구·판 진행·별사탕·카드 패널·최고기록 미터·
고양이 대사·버튼 넷이 있다. 여기에 목표 줄을 셋 얹으면 대시보드가 되고
아무것도 안 남는다. **하나를 골라 크게 보여주는 것**이 기능의 전부다.

### 후보

1. **최고기록** — `bestScore - score`
2. **점수 카드** — `score-4000`, `score-10000` (`metric: 'bestScore'`)
3. **누적 카드** — `ten-runs`, `cats-300`, `big-300`, `cells-20000`

### 거르는 규칙 두 가지

**① 노력으로 좁혀지는 것만.** `days-7` / `days-30`은 달력이 정하지 실력이
아니다. 헤드라인에 절대 올리지 않는다(갤러리에는 그대로 둔다).

**② 한두 판 안에 닿을 것만.** 최고 7,760인데 `지운 칸 20,000개`(현재 3,400)를
내미는 것은 목표가 아니라 벽이다.

도달 거리는 **그 사람 자신의 기록으로** 잰다 — 전역 상수를 박지 않는다.
누적값과 판 수가 이미 저장돼 있으므로 판당 평균이 공짜로 나온다.

```
판당평균 = 누적값 / max(1, 플레이한 판 수)
남은판수 = (목표 - 현재) / 판당평균
```

`남은판수 <= 3`인 것만 후보로 남긴다. 자기 기록에서 나오므로 초보에게는
초보의 속도로, 숙련자에게는 숙련자의 속도로 자동으로 맞는다.

점수 목표는 누적이 아니라 최댓값이라 이 식이 안 맞는다. 대신 지금 쓰는
근접 기준을 그대로 쓴다: `차이 <= max(1500, 목표 * 0.25)`.

판을 두 번도 안 한 사람(`runs < 2`)은 판당 평균이 못 미더우므로 점수 목표만
본다.

### 고르는 순서

남은 후보 중 **가장 가까운 것 하나**. 동률이면 최고기록 > 점수 카드 >
누적 카드 순. 하나도 안 남으면 **아무것도 안 띄운다** — 억지 목표는 없느니만
못하다(이 판단이 이 기능에서 제일 중요하다).

## 어디에 그리는가

같은 선택기를 두 군데서 쓴다.

**① 결과창** — '한 판 더!' 버튼 바로 위.

```
8,000점까지 180점!
```

지금 그 자리의 `최고기록 도전 N%` 미터를 대신한다. 퍼센트는 "얼마나 왔나"를
말하고 이 줄은 "얼마나 남았나"를 말한다. 뒤쪽이 행동을 만든다. 미터는 지운다.

**② 시작 카운트다운** — 지금 비어 있는 자리다.

```
이번 판 8,000점이면 새 카드!
```

끝날 때의 목표는 "한 판 더 할 이유"지만, **시작할 때의 목표는 이 판을 어떻게
칠지의 기준**이다. 같은 문장이 여기서 더 값지다.

홈 화면에는 넣지 않는다. 이미 사탕 개수와 최고점수가 있고 하단이 빡빡하다.

## 문구

| 상황 | 문구 |
| --- | --- |
| 최고기록 | `최고기록까지 180점!` |
| 점수 카드 | `8,000점이면 새 카드!` (카드 이름은 안 쓴다 — 아직 못 본 카드다) |
| 누적 카드 | `고양이 12마리만 더 모으면 새 카드!` |
| 신기록을 낸 판 | 목표 줄 대신 기존 NEW RECORD 연출. 겹치지 않는다 |
| 후보 없음 | 아무것도 안 뜬다 |

## 안 하는 것

- 자체 랭킹 서버·계정·닉네임·치팅 방지 — 그대로 안 만든다
- 토스 랭킹 화면 — 우리가 못 고친다. 손대지 않는다
- **"최근 5판 중 2위"류** — 뒤로 갈 수 있는 지표라서 뺀다. 컨디션 나쁜 날엔
  계속 하위가 뜨고, 그건 목표가 아니라 잔소리가 된다. 최고기록과 카드 조건은
  절대 멀어지지 않는다는 성질이 목표로서 결정적이다
- **"지난 판보다 +640점"을 주인공으로 쓰는 것** — 뒤를 보는 문장이라 엔진이
  못 된다. 작은 보조 줄로는 이미 있고 그대로 둔다

## 시험으로 지킬 것

- 달력 카드(`days-7`, `days-30`)는 어떤 입력에서도 헤드라인이 되지 않는다
- `남은판수 > 3`인 목표는 안 뜬다
- 후보가 없으면 빈 문자열을 돌려준다(억지 목표 금지)
- `runs = 0`, `runs = 1`, 누적값 0에서 나눗셈이 깨지지 않는다
- 신기록 판에서는 목표 줄과 NEW RECORD가 같이 뜨지 않는다
- 결과창과 시작 카운트다운이 **같은 목표**를 말한다(두 군데가 다른 말을 하면
  안 된다 — 예전에 결과 헤드라인과 재시도 버튼이 서로 다른 말을 한 적이 있다)

## 크기

`js/data.js`에 선택기 하나(순수 함수), 결과창 한 줄 교체, 시작 카운트다운
한 줄 추가, 시험 한 벌. 새 그림 없음, 새 화면 없음, 저장소 변경 없음.

## 왜 별사탕보다 먼저인가

"며칠 뒤 왜 다시 켜지"의 답으로 `1,240점만 더 하면 카드`가 `고양이가 반응해
줘서`보다 세다. 그리고 앞쪽은 이미 있는 부품으로 만든다. 별사탕은 이미
나갔으니 둘 중 하나를 고르는 문제가 아니라 다음에 뭘 하느냐의 문제다.
